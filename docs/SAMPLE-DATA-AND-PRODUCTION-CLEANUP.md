# Sample data layer: what was built and how to remove it for production

Last updated: 2026-11-12

This document explains the sample (dummy) data layer added to the frontend, lists every file it touches, and gives the steps to remove it when the dashboards move to the real DART API.

Sources of truth: `dart-api.yaml` and `dart-api-frontend-guide.md` (both read-only). Every sample response follows them.

---

## 1. Summary

The dashboards call the same API functions in development and production. Only the transport differs:

- **Sample mode (default today):** a fake transport answers each request from a stored copy of the spec responses in `frontend/src/data.ts`. No backend is needed.
- **Live mode:** requests go to `API_BASE_URL` (through the `/api` rewrite in `next.config.ts`).

The sample data is generated, not hand-typed. To change it, edit the seed file and run the generator. Nothing in the UI, hooks or endpoint files knows the data is fake.

**Sample figures are invented.** The company names (except the three IDs), category names, account names and account codes are placeholders, not CPF data.

---

## 2. How a request flows

```
Screen / hook (useSummary, useTrend, ...)
  -> lib/api/<endpoint>.ts            builds the query parameters
  -> lib/api/client.ts (apiClient)    axios instance; errors normalised to NormalisedError

  Sample mode (USE_MOCK_DATA = true):
    client.ts sampleTransport  -> lib/api/sampleRouter.ts (validation, 403/404 rules)
                                -> lib/api/sampleKey.ts (canonical key)
                                -> src/data.ts (stored spec response)

  Live mode (USE_MOCK_DATA = false):
    axios -> /api/... -> next.config.ts rewrite -> API_BASE_URL -> real DART API
```

Errors reach the UI in the same shape in both modes: `{ code, message, requestId, details? }`. Screens branch on `code`, not the HTTP status.

## 4. Production switch-over checklist

Work through these in order.

### 4.1 Make live mode the default
- `frontend/src/lib/constants.ts` currently reads `USE_MOCK_DATA = process.env.NEXT_PUBLIC_USE_MOCK !== "false"`. **Sample mode is on unless that variable is set to `false`.** A missing variable in production would therefore serve fake data.
- Step 1: set `NEXT_PUBLIC_USE_MOCK=false` in every production environment (Vercel project settings).
- Step 2: remove `USE_MOCK_DATA` entirely as part of 4.3.

### 4.2 Connect the real API
- Set `API_BASE_URL` (in `.env.local` for development, and in the hosting environment for production). Check that `next.config.ts` rewrites `/api` to it.
- Make sure every request carries `Authorization: Bearer <JWT>` once sign-in is built (spec section 4).

### 4.3 Replace the sample user
- `CURRENT_USER` in `constants.ts` is a sample name and email. Replace it with the signed-in user from the session, and update `Header.tsx` and `Sidebar.tsx` to read it.

### 4.4 Delete the sample-only files
Delete the files in section 3.1:
```
frontend/src/data.ts
frontend/scripts/                       (whole folder)
frontend/src/lib/api/sampleRouter.ts
frontend/src/lib/api/sampleKey.ts
frontend/src/lib/api/sample.test.ts
frontend/src/lib/periods.ts
frontend/src/lib/periods.test.ts
```
Then:
- Remove the `generate:data` script from `frontend/package.json`.
- Remove `"allowImportingTsExtensions": true` from `frontend/tsconfig.json`.
- Edit `client.ts`, `constants.ts`, `Header.tsx` and `Sidebar.tsx` as listed in 3.2.

### 4.5 Confirm nothing sample-related is left
Run these from `frontend/`. Each should return nothing:
```
grep -rn "sampleRouter\|sampleKey\|sampleTransport\|SAMPLE_\|from \"@/data\"\|USE_MOCK\|NEXT_PUBLIC_USE_MOCK\|CURRENT_USER\|lib/periods\|generate:data" src scripts package.json tsconfig.json
```
(`scripts/` should no longer exist.)

### 4.6 Check the build
```
npm run typecheck
npm run lint
npm run test
npm run build
```
Then check the build output does not contain the sample figures (for example search the `.next` output for "Oct–Nov 2026"). It should not.

### 4.7 Test against the real API
With `NEXT_PUBLIC_USE_MOCK=false` and `API_BASE_URL` pointing at the real API, check each page for:
- the company filter, including a company the user cannot see (expect "Not loaded" or the forbidden message, handled by `QueryPanel`);
- a period with no data (expect "No data for this period yet" and the "Show" button);
- a partial year (labels such as "Jan–May 2026" come from the API, not the UI);
- negative amounts in a category (pie fallback);
- a network or server failure (expect the request ID to show).

## 5. How to change the sample data (while it is still in use)

1. Edit `frontend/scripts/data.seed.ts`. Change company figures, categories, account names or weights, or `SEED.latestClosed`.
2. Run `npm run generate:data` from `frontend/`.
3. Run `npm run test`. `sample.test.ts` checks that the new data is valid and that totals agree.

Notes:
- Only the group and each single company are stored. Other company combinations return 404.
- Account lists are stored only for the default sort (`-amount`) and default page size (25). Other sort orders return 404 in sample mode.
- Trend points for periods that are not complete carry null amounts, as the spec requires.
- 2021 has no prior year in the data, so its comparisons are zero, with null percentages.

---

## 6. Rules the sample data follows (from the spec)

- Amounts are whole cents while summing, then output as KES numbers rounded to 2 decimals.
- Only complete months are reported. A partial period is cut to its complete months, and `periodLabel` and `comparison.label` say which months.
- Year-end closing entries are excluded. A period with no complete month returns 404 `DATA_NOT_AVAILABLE`.
- `OTHERS` is a breakdown roll-up only (beyond `top`). It is never a drill-down category and returns 404 `NOT_FOUND`.
- A company the user cannot see, or that does not exist, returns 403 `FORBIDDEN_COMPANY`.
- Quarter and month together return 400 `VALIDATION_ERROR`.
- Every error carries a `requestId`, which matches the `X-Request-ID` header.
